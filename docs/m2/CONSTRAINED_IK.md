# M2 constrained canonical IK

Issue #19 adds a bounded inverse-kinematics core to `DeferredTeleopRuntime`. It
operates on the canonical robot description already used by FK: right-handed,
Z-up, metres, radians and double precision. The solver has no actor, camera,
hardware, collision or dynamics dependency.

## Task contract

`SolveInverseKinematics` receives an explicit `FDttIKRequest` containing:

- a named revolute joint group and a named tool frame;
- a canonical target position and an explicit canonical root pose;
- a complete named seed for every revolute joint in the description;
- `PositionOnly`, or `PositionPlusApproachAxis` with a finite non-zero target
  direction and finite non-zero tool-local axis.

Position-only mode does not read either approach-axis field. The approach mode
constrains two orientation rows while leaving roll around the approach axis
free. This is a position-plus-axis task, never an arbitrary six-degree-of-
freedom pose claim. Joints outside the selected group remain byte-for-byte at
their seed values; only active joints are projected to structural limits.

## Deterministic numerical policy

The default settings are position weight `1`, approach weight `0.10`, DLS
lambda `0.02` clamped to `[0.001, 1]`, maximum joint step `0.12 rad`, position
tolerance `1e-3 m`, approach tolerance `2 degrees`, 64 iterations and 1024
full FK evaluations. The central-difference step is `1e-5 rad`; at most five
backtracking candidates (`1, 1/2, 1/4, 1/8, 1/16`) and four damping trials
are considered per iteration.

Each initial, central-difference and line-search state call is counted before
FK starts. A call that would exceed `MaxFKEvaluations` is not started. The
evaluation count is therefore a deterministic work budget, not a wall-clock
promise.

For the approach task, let `a` be the current world tool axis and `b` the
normalized target direction:

```text
d     = clamp(dot(a, b), -1, 1)
theta = atan2(|cross(a, b)|, d)
e3    = (theta / sin(theta)) * (b - d*a)
```

The zero-angle limit is zero. At exact antiparallel input, `e3 = pi*u`, where
`u` is the projection of the least-aligned canonical basis axis onto the
tangent plane; `v = a x u`. The two approach rows are `e3.u`, `e3.v`, and
central finite differences use the same `u,v` basis. This gives the expected
positive sign for a +Y joint taking a +Z tool axis toward +X.

The DLS update is:

```text
dq = J^T (J J^T + lambda^2 I)^-1 e
```

The 3×3 or 5×5 system uses deterministic partial pivoting. Candidate states
are projected to active joint limits. A non-converged candidate must improve
the weighted cost by more than `StagnationCostTolerance`; a candidate that
satisfies both task tolerances is copied and accepted immediately, even when
its weighted cost is higher than another infeasible candidate. The best state
seen, including the projected seed, is retained when the solve stagnates or
reaches a budget.

## Result and limitations

`FDttIKResult` returns the model reference, the explicit `ToolFrameName`, all
revolute positions in description order, the active group order, active limit
flags, achieved tool transform, unweighted position and approach residuals,
iteration count, FK evaluation count and diagnostics.
Statuses are `Converged`, `Partial`, `IterationLimit`, `InvalidInput` and
`NumericalFailure`; `Unreachable` is reserved and is not emitted for a local
solver failure because no workspace-wide proof is attempted.

`Partial` means deterministic stagnation. `IterationLimit` means the iteration
or FK budget ended before convergence. A valid result is a conditional
`KinematicPreview` input; it is not a motion plan, safety proof or actuator
command. Unreal build and Automation Test execution remain the responsibility
of the project validation stage.

The four-DOF hand-built approach-axis regression case intentionally starts far
from a target generated by FK and may settle at a finite local residual. That
test records `Partial` or `IterationLimit` with the normal budgets and does not
label the local result `Unreachable`. A nearby seed for the same target is
required to converge under the unchanged default tolerances. The separate
free-roll fixture uses a tool offset parallel to the wrist roll axis; changing
only that roll therefore preserves both the target position and the
constrained approach axis. It does not test or claim a full orientation goal.

## Automation evidence boundary

The generic-group automation fixture has six active revolute joints. Five
coaxial Z joints start at zero and the sixth joint rotates about Y; with a unit
X tool offset, the target at `q6 = 0.4 rad` is
`(cos(0.4), 0, -sin(0.4))`. The test requires the sixth joint to move and at
least the initial FK plus its six-column central Jacobian and one candidate FK
to be counted. This prevents an immediate success at the seed from passing a
mere `Num() > 5` check.

The singular rotation-center fixture requests a translated position from a
tool whose position Jacobian is identically zero. It uses the normal FK budget,
requires more than one FK evaluation, and accepts only `Partial` or
`IterationLimit`; it also checks finite output and joint limits. The local
solver does not emit `Unreachable`, because that status would require a
workspace-wide proof.

`CentralJacobian.ReferenceFivePoint` keeps the independent FK finite-difference
oracle: it evaluates every permuted active joint at `-2h, -h, +h, +2h` and
compares the five-point derivative with the production central derivative for
all three position rows and all five position-plus-approach rows. A private
`WITH_DEV_AUTOMATION_TESTS` bridge reconstructs the solver snapshots and calls
the actual `BuildTaskErrorAndJacobian`; it exposes only this test result and
does not alter the public API. The oracle also independently constructs the
approach `u,v` basis and checks the non-default position/orientation weights,
root transform and named group-column permutation.

The candidate-policy regression invokes the private production selection helper
under `WITH_DEV_AUTOMATION_TESTS`. It supplies a cheaper candidate that misses
the 1 mm position tolerance and a more expensive candidate at 0.5 mm and
0.01 rad; the latter must be selected as converged. This keeps the policy
check coupled to the solver path without adding public API surface.

The SO-101 solve regression loads the committed
`robots/so101/generated/so101.kinematics.json` through the canonical parser,
checks its source commit/blob pin, five-joint arm group and separate gripper
group, and supplies all six revolute seed values. Position-only and
position-plus-approach-axis goals are generated from a nonzero warm target;
the gripper remains at its seed value.
