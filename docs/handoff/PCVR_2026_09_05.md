## Task B — operator: a small useful Blueprint interface

Do this after native validation, before visual polishing.

Create an isolated PCVR test map with:

- the existing robot reference view, one separate blue local candidate and a grabbable target;
- the authoring component, an explicit source-selection/rebase action, and the two IK modes;
- a trajectory polyline with a few relative-time markers;
- status, target/achieved residuals, source age/revision and solve-duration labels;
- `Freeze locally`, `Clear` and `Reset target to source tool` actions.

Start with PositionOnly and an identity site anchor. Hand motion changes the handle; the robot
only follows while editing is active. Feed changed goals, not every unchanged hand sample. On
release, submit the final sample to the component and wait for its result before freezing. There
is no physical submit, task dispatch or controller-to-motor mapping in this test.

Use `GetSourceModelAndState` to initialize the separate candidate. On each current accepted
preview, apply the accepted IK joint vector and render the supplied tool samples. Do not recompute
IK in Blueprint, convert metres twice, or overwrite Mission's Target actor with this local input.

The fixture path contains synthetic data. Keep the replay label visible. The first target-source
selection is confirmed-only; future Arrival authoring must retain predicted provenance explicitly.

## Task C — operator: manual acceptance session

Record yes/no plus a short observation, not just a pleasant-looking video.

| Check | Expected behavior |
|---|---|
| Reachable small drag | Candidate follows without topology rebuilding or abrupt zero reset |
| Hand release | Last pose settles; no queued burst; Freeze refers to the final input |
| Fast drag | Input coalesces; solve rate stays bounded; no backlog after stopping |
| Unreachable goal | Handle stays requested; achieved pose/status differ visibly; Freeze unavailable |
| Reset | Handle returns to the selected tool pose without silently rebasing evidence |
| Approach-axis mode | Position and approach direction matter; free roll is not falsely constrained |
| Explicit source rebase | Previous candidate becomes noncurrent/clears; no hidden jump during grab |
| Tracking loss / Clear | Pending freeze/goal is cancelled locally; no command is emitted |
| Mission disconnect | Remote layers show degraded freshness; local snapshot work is labelled offline |
| Scale/origin | Metre scale and handedness look right; no actor-scale workaround |
| Restart PIE/editor | Fixture or live source initializes explicitly; no stale transient-only scene |
| Several minutes in headset | Readable depth/layers, tolerable jitter, no major frame stalls |

The human outcomes are UX observations, not physical-safety validation. Keep a 20–40 second
capture showing a reachable goal, an invalid goal and source/candidate distinction. Include the
commit and headset/runtime in the note. Controller mapping, handle size, opacity, line thickness
and text placement are the operator's design choices.
